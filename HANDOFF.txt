ORIGIN
Built for the DEV/Hacktoberfest 2026 Week 1 "Touch Grass" challenge. Deadline: Oct 11, 2026, 11:59 PM PDT.
Brief: offline-first mobile PWA; open-weight/local AI at the core; zero paid inference; AI writes real-world
outdoor missions, user leaves the screen, returns to verify and reflect. Firebase project nature-quest-c14be.

KNOWN ISSUES
- Backup is push-only: no pull/restore on a new device. Needs Firestore enabled + rules (see README).
- Endpoint provider from an https page can only reach http://localhost (desktop) - a phone cannot reach a
  LAN http server (mixed content). On phones use the on-device model. Ollama needs OLLAMA_ORIGINS set.
- Completion is self-reported only (verification arrives in CP5). Wake Lock is deliberately not used.
- evaluateQuestResponse() intentionally not implemented (belongs to CP5 verification).

DO NOT TOUCH
- js/store.js outbox id scheme (owner|entity|record|rev): sync dedupe relies on it.
- js/quest/model.js transition(): single source of truth for lifecycle; always go through engine.moveQuest.
- js/quest/safety.js rules + engine safety check on ALL quest text (AI and static). Add rules, never bypass.
- sw.js: bump VERSION when shell files change and keep the SHELL list in sync with new files.
- app.js controllerchange guard (no reload on first install).

UPDATE 2 (real-phone findings)
Device: Android 10 Chrome, 8 GB, WebGPU API present but NO adapter ("Failed to get GPU adapter"). CPU WASM with
Qwen2.5-0.5B q4 measured ~0.3 tokens/s (load 19s, first token 15s) = unusable for a whole quest.
Changes: default model now SmolLM2-135M-Instruct (q4, ~200 MB, selectable; Qwen kept as "Better writing");
GPU only tried if requestAdapter() succeeds; prompt and output shortened (<=130 tokens); model requests are queued.
js/ai/pantry.js writes the likely next quest in the background while on Home and stores validated drafts, so the
one-tap quest is instant when one is ready; otherwise the person watches it stream (skip button) or gets the library.
Tests: node quest 13, ai 13, loop 11, verify 12, pantry 8. Browser smoke 15, ai_hang 11, ai_ui 9, loop_ui 15, photo_ui 9.
STILL UNVERIFIED: SmolLM2-135M speed and wording quality on the real phone. If still too slow, options in order:

UPDATE 3 (product decision after real-phone tests)
SmolLM2-135M was faster but rambled and never finished a quest on the test phone. Decision: stop free-writing by default.
Quests = 30 checked library missions (js/quest/fallback.js, with mood tags). js/ai/matcher.js uses all-MiniLM-L6-v2 (~25 MB)
to RE-ORDER safe candidates by meaning (typed mood, time of day, season, company, energy); 7s cap then rules-based pick, so
the screen never waits. Free-writing (pantry/browser/endpoint providers) kept but off by default ("experimental").
UI: quest card shows Why this / Your task / Time; "Show me another" abandons and creates a different quest instantly;
Home offers one-time "turn on on-device AI" (25 MB). Old configs with writing enabled are migrated to off (cfg.v2).
Tests: node quest 13, ai 13, loop 11, verify 12, pantry 8, match 8. Browser: smoke 15, match_ui 10, ai_hang 11, ai_ui 9,
loop_ui 15, photo_ui 9. UNVERIFIED on a real phone: MiniLM download/speed (use You > On-device AI > Test matching).
